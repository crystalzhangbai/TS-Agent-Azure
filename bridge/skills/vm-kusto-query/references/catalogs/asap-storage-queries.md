# ASAP / SmartNIC / Boost-for-Storage NVMe — Kusto Queries

Storage Acceleration Platform (ASAP) telemetry from SmartNIC-offloaded NVMe stack.
On AMD `*_v6` / `*_v7` SKUs (and other Boost-for-Storage configurations), a
host-side ASAP NVMe Controller Reset produces the exact same "guest hang"
signature in Geneva (CPU/IO drop to zero) — but container/node still report
Healthy, so Service Healing / NodeFault / VMA / Kronox / LogContainerHealthSnapshot
all miss it. The queries below are the canonical platform-side probes.

## Primary cluster and objects

```kusto
cluster('storageclient.eastus.kusto.windows.net').database('Fa')
```

| Object | Purpose |
|---|---|
| `AsapNvmeEtwTraceLogEventView` | NVMe-facing ASAP ETW events. Queue, namespace, completion, controller reset, guest-facing controller activity. |
| `AsapPfEtwTraceLogEventView` | Physical Function / VF management events. VM create, restart, cleanup, VF reset, namespace attach/detach. |
| `AsapKmsEtwTraceLogEventView` | KMS coordination events. Hyper-V/UMED/VHDMP coordination, restart, servicing, LM. |
| `GetAsapEventsOverlake2(nodeId, startTime, endTime)` | Aggregated PF/KMS/UMED/NVMe timeline for an Overlake2 node. Preferred first-pass timeline. |
| `OsAsapCounterTable` | Per-disk ASAP counters from OsDiag. Latency, IOPS/BPS, FO/PO, exceptions, disk metadata. |
| `OsAsapNodeCounterTable` | Node-level ASAP counter health, including missed event / latency sample windows. |
| `AsapMapVmToDiskOVL2()` | Map VM (container/VF) to disk surface on Overlake2 nodes. |

> In-guest correlated tells: Windows `stornvme` controller reset event,
> Linux `nvme nvmeX: I/O timeout`. EEE indicator: "ASAP Controller Reset,
> Message: VfId N".

---

## Canonical controller-reset probe

Run this first when AMD v6/v7 (or any Boost-for-Storage SKU) shows guest hang
with platform tables clean.

```kusto
let _nodeId = "<nodeId>";
let _startTime = datetime(2026-03-11 08:00:00);
let _endTime = datetime(2026-03-11 09:00:00);
cluster('storageclient.eastus.kusto.windows.net').database('Fa').AsapNvmeEtwTraceLogEventView
| where NodeId == _nodeId
| where PreciseTimeStamp between (_startTime .. _endTime)
| where Message has "Controller Reset" or Message has "VfId"
| project PreciseTimeStamp, NodeId, VfId, Message, EventId
| order by PreciseTimeStamp asc
```

Any hit = host-side ASAP fault, **not** guest issue. Escalate to **EEE Storage**
team with the node, VfId, and timestamp.

## Unified event timeline (preferred first pass)

```kusto
let _nodeId = "<nodeId>";
let _startTime = datetime(2026-03-11 08:00:00);
let _endTime = datetime(2026-03-11 09:00:00);
cluster('storageclient.eastus.kusto.windows.net').database('Fa')
.GetAsapEventsOverlake2(_nodeId, _startTime, _endTime)
| order by PreciseTimeStamp asc
```

Component-specific fallback when `GetAsapEventsOverlake2` is unavailable:

```kusto
let _nodeId = "<nodeId>";
let _startTime = datetime(2026-03-11 08:00:00);
let _endTime = datetime(2026-03-11 09:00:00);
union withsource=SourceTable
(
    cluster('storageclient.eastus.kusto.windows.net').database('Fa').AsapNvmeEtwTraceLogEventView
    | where NodeId == _nodeId
    | where PreciseTimeStamp between (_startTime .. _endTime)
),
(
    cluster('storageclient.eastus.kusto.windows.net').database('Fa').AsapPfEtwTraceLogEventView
    | where NodeId == _nodeId
    | where PreciseTimeStamp between (_startTime .. _endTime)
),
(
    cluster('storageclient.eastus.kusto.windows.net').database('Fa').AsapKmsEtwTraceLogEventView
    | where NodeId == _nodeId
    | where PreciseTimeStamp between (_startTime .. _endTime)
)
| order by PreciseTimeStamp asc
```

Adjust column projection after `getschema`; different views expose different
message fields.

## `OsAsapCounterTable` — per-disk counters

Generated by OsDiag. Contains counters for each ASAP disk on a node. New disks
sampled every 5 seconds for the first 10 minutes, then every 5 minutes.

### Disk metadata columns

| Column | Meaning |
|---|---|
| `OsDiagHostTimeStamp` | Telemetry capture time. |
| `NamespaceName` | Disk/namespace name, roughly equivalent to surface name. |
| `ContainerId` | VM container GUID hosting the disk. |
| `BlobPath` | Blob path URL for the disk. |
| `ArmId` | Disk ARM ID. |
| `ControllerType` / `ControllerId` | Disk controller type and controller address. |
| `DiskType` | OS/data/resource/VMGS disk role. |
| `IsHardwareMode` | Whether disk is currently in hardware mode (FO/PO) or handled by KMS/host. |
| `IsNewDisk` | Disk appeared on the node in the last 10 minutes. |
| `BackingStoreType`, `BackingStoreIndex` | BlobCache/backing-store association. |
| `CachePolicy` | BlobCache cache policy. |

### Basic performance counters

| Group | Counters |
|---|---|
| IO volume | `IOPS`, `ReadIOPS`, `WriteIOPS`, `BPS`, `ReadBPS`, `WriteBPS` |
| Queue and latency | `QD`, `AverageLatency`, `AverageReadLatency`, `AverageWriteLatency` |
| Min/max sampling | `MinIOPS`, `MaxIOPS`, `MinQueueDepth`, `MaxQueueDepth`, read/write min/max counters |
| Total/delta | `Total*` since disk attach; `Delta*` since previous sample |

### FO/PO and dashboard counters

| Counters | Meaning |
|---|---|
| `DeltaPoReadCompleted`, `DeltaPoWriteCompleted` | Partial Offload read/write completions in sample window. |
| `DeltaFoReadCompleted`, `DeltaFoWriteCompleted` | Full Offload read/write completions in sample window. |
| `DeltaPoBytesCompleted`, `DeltaFoBytesCompleted` | Bytes completed by PO/FO path. |
| `PoCompletedPercent`, `PoSessions`, `FoSessions` | Dashboard-level offload/session indicators when populated. |
| `SchedulerTableBwDelay`, `SchedulerTableIopsDelay` | Scheduler delay indicators. |

### Exception counters

| Counter | Investigation direction |
|---|---|
| `DeltaBqeTimeoutExceptions` | Backend Queue Entry timeout; inspect backend/RNIC/path and event timeline. |
| `DeltaSwingTimeoutExceptions` | Swing command timeout; correlate with backend command/session events. |
| `DeltaXioTimeoutExceptions` | XIO remote end timeout; inspect XIO/storage backend health. |
| `DeltaXioInvalidSessionExceptions` | Session issue; inspect session refresh and backend state. |
| `DeltaXioHttpStatusNotOkExceptions` | Backend returned non-OK status; inspect full event/error payload. |
| `DeltaCrcMismatchExceptions` | CRC mismatch; escalate as potential data integrity signal. |
| `DeltaBqeExceptions` | Generic BQE exception; inspect event details. |
| `DeltaSessionRefreshCount` | Session refresh activity; correlate with invalid session or backend failover. |

### Latency breakdown counters

Use delta latency bucket counters to localize where latency occurred:

| Counter family | Stage |
|---|---|
| `DeltaSchedLatency*` | Scheduler hardware pipeline stage. |
| `DeltaBqeLatency*` | Between BQE creation and BQE deletion. |
| `DeltaBackendLatency*` | Backend-reported latency, FO mode only. |
| `DeltaIoLatency*` | Overall NVMe SQ fetch to NVMe CQ completion. |

For each family, inspect `*SampleCount`, `*MaxLatency`, and `*LatencySum`.
Compute average only when sample count is non-zero.

### Counter starter query

```kusto
let _containerId = "<containerId>";
let _startTime = datetime(2026-03-11 08:00:00);
let _endTime = datetime(2026-03-11 09:00:00);
cluster('storageclient.eastus.kusto.windows.net').database('Fa').OsAsapCounterTable
| where ContainerId =~ _containerId
| where OsDiagHostTimeStamp between (_startTime .. _endTime)
| project
    OsDiagHostTimeStamp,
    NamespaceName,
    ArmId,
    DiskType,
    IsHardwareMode,
    IOPS,
    ReadIOPS,
    WriteIOPS,
    BPS,
    ReadBPS,
    WriteBPS,
    QD,
    AverageLatency,
    AverageReadLatency,
    AverageWriteLatency,
    DeltaPoReadCompleted,
    DeltaPoWriteCompleted,
    DeltaFoReadCompleted,
    DeltaFoWriteCompleted,
    DeltaBqeTimeoutExceptions,
    DeltaSwingTimeoutExceptions,
    DeltaXioTimeoutExceptions,
    DeltaXioInvalidSessionExceptions,
    DeltaXioHttpStatusNotOkExceptions,
    DeltaCrcMismatchExceptions,
    DeltaSessionRefreshCount
| order by OsDiagHostTimeStamp asc
```

### Latency breakdown query

```kusto
let _containerId = "<containerId>";
let _startTime = datetime(2026-03-11 08:00:00);
let _endTime = datetime(2026-03-11 09:00:00);
cluster('storageclient.eastus.kusto.windows.net').database('Fa').OsAsapCounterTable
| where ContainerId =~ _containerId
| where OsDiagHostTimeStamp between (_startTime .. _endTime)
| extend
    AvgSchedReadUs = iif(DeltaSchedLatencyDiskReadIoBucketSampleCount > 0, todouble(DeltaSchedLatencyDiskReadIoBucketLatencySum) / DeltaSchedLatencyDiskReadIoBucketSampleCount, real(null)),
    AvgBqeReadUs = iif(DeltaBqeLatencyDiskReadIoBucketSampleCount > 0, todouble(DeltaBqeLatencyDiskReadIoBucketLatencySum) / DeltaBqeLatencyDiskReadIoBucketSampleCount, real(null)),
    AvgBackendReadUs = iif(DeltaBackendLatencyDiskReadIoBucketSampleCount > 0, todouble(DeltaBackendLatencyDiskReadIoBucketLatencySum) / DeltaBackendLatencyDiskReadIoBucketSampleCount, real(null)),
    AvgIoReadUs = iif(DeltaIoLatencyDiskReadIoBucketSampleCount > 0, todouble(DeltaIoLatencyDiskReadIoBucketLatencySum) / DeltaIoLatencyDiskReadIoBucketSampleCount, real(null))
| project OsDiagHostTimeStamp, NamespaceName, ArmId,
    AvgSchedReadUs, AvgBqeReadUs, AvgBackendReadUs, AvgIoReadUs,
    DeltaSchedLatencyDiskReadIoBucketMaxLatency,
    DeltaBqeLatencyDiskReadIoBucketMaxLatency,
    DeltaBackendLatencyDiskReadIoBucketMaxLatency,
    DeltaIoLatencyDiskReadIoBucketMaxLatency
| order by OsDiagHostTimeStamp asc
```

## `OsAsapNodeCounterTable` — node-level health

| Counter | Meaning |
|---|---|
| `TotalEventTableMissed` / `DeltaEventTableMissed` | Missed KMS event samples. |
| `TotalLatencyWindowsMissed` / `DeltaLatencyWindowsMissed` | Missed latency sample windows. |

If these are non-zero in the issue window, state that ASAP telemetry may have
gaps and avoid overconfident negative conclusions.

## Interpretation cheatsheet

| Signal | Likely direction |
|---|---|
| Controller Reset events on `AsapNvmeEtwTraceLogEventView` | Host ASAP fault → EEE Storage |
| FO path dominant + backend latency rising | Backend/storage path or RNIC delay |
| PO/SWPE activity or fallback rising | Cache, servicing, internal ASAP exceptions, host SW path redirect |
| BQE/XIO/Swing timeouts or invalid sessions | Backend timeouts, session refresh, RDMA/RNIC, XIO health |
| CRC mismatch | High-severity data integrity → escalate immediately |
| KMS/PF errors during restart/LM | VF reset, namespace detach/attach, queue create/delete, UMED, host servicing |

---

## Escalation

If host-side ASAP fault is confirmed (controller reset, CRC mismatch, persistent
BQE/XIO timeouts):

1. Collect: NodeId, VfId, ContainerId, timestamps, exact event Message strings.
2. Snapshot the counter query output for the issue window.
3. Escalate to **EEE Storage** team with all of the above.
