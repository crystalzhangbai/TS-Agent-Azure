# Draft FQR Email via DFM (Browser Automation)

**Primary Use**: Automate First Quality Response (FQR) email drafting in DFM (Dynamics 365 Field Manager)  
**URL**: `https://aka.ms/dfm` → redirects to `https://onesupport.crm.dynamics.com/main.aspx?appid=...`  
**Tool**: Use `playwright-cli` skill for browser automation (fall back to `playwright-browser_*` MCP tools if `playwright-cli` is unavailable)  
**Trigger Words**: `draft fqr`, `fqr email`, `first quality response`, `首次质量回复`, `dfm email`

#### Prerequisites
- `playwright-cli` skill available (or Playwright MCP as fallback)
- User authenticated to DFM / Dynamics 365
- Case ID provided by user
- Support engineer's display name for CC (e.g., "Frank Shi")

#### Workflow Steps

```
Step 1: Navigate to DFM
        → playwright-browser_navigate url="https://aka.ms/dfm"
        → wait_for time=8 (SSO + Dynamics load)
        → If Copilot dialog appears, evaluate to dismiss it

Step 2: Search for Case
        → snapshot → find searchbox "Search" ref
        → type ref=... text="<case_id>" submit=true
        → wait_for time=3 for search results

Step 3: Open Case
        → snapshot → find the case number gridcell/link ref
        → click ref=... (double-click if single click only selects row)
        → wait_for time=5 for case page to load

Step 4: Navigate to Timeline → Create Email
        → snapshot → click tab "Timeline" ref
        → wait_for time=3
        → snapshot → click button "Create a timeline record." ref
        → snapshot → click menuitem "Email Activity" ref
        → wait_for time=5 for email form to load

Step 5: Fill CC (add support engineer)
        → snapshot → find combobox "Cc, Multiple Selection Lookup" ref
        → type ref=... text="<engineer_display_name>" slowly=true
        → wait_for time=3 for lookup results
        → snapshot → click matching treeitem ref
        → press_key key="Escape" to close dropdown

Step 6: DO NOT modify Subject
        ⚠️ Subject is auto-generated by DFM — leave it unchanged

        → snapshot → find button "Close" inside group "Draft with Copilot" ref
        → click ref=...

        → OR click menuitem "Save (CTRL+S)" ref to save as draft
```

#### Body Editor Injection (Critical)

The email body uses **RichTextEditorV2 (CKEditor 5)**. Direct DOM manipulation (`innerHTML`, `insertHTML`, `execCommand`) does **NOT** work — the editor's internal model ignores DOM changes.

**Preferred method: CKEditor API `setData()`** (most reliable, preserves signature)

```js
() => {
  const editorElement = document.querySelector('[aria-label="Rich Text Editor Control email description"]');
  if (!editorElement) return 'editor not found';
  const editor = editorElement.ckeditorInstance;
  if (!editor) return 'CKEditor instance not found';
  
  // 1. Get current data to preserve signature
  const currentData = editor.getData();
  const signatureIndex = currentData.indexOf('id="signature"');
  if (signatureIndex === -1) return 'signature not found';
  const sigDivStart = currentData.lastIndexOf('<div', signatureIndex);
  const signatureHTML = currentData.substring(sigDivStart);
  
  // 2. Build FQR HTML content (use concrete findings from B01 investigation)
  const fqrHTML = `<div style="font-family:'Segoe UI','Helvetica Neue',sans-serif;font-size:11pt;" dir="ltr">
<p>Hi [Customer Name],</p>
<p>&nbsp;</p>
<p>[FQR body with concrete B01 findings — NOT generic placeholders]</p>
<p>&nbsp;</p>
</div>`;
  
  // 3. Set data: FQR content + preserved signature
  editor.setData(fqrHTML + signatureHTML);
  return 'FQR content injected via CKEditor API';
}
```

**Alternative method: ClipboardEvent paste** (fallback if ckeditorInstance is unavailable)

```js
() => {
  const editor = document.querySelector('[aria-label="Rich Text Editor Control email description"]');
  if (!editor) return 'editor not found';
  
  // 1. Focus and position cursor at the beginning (before signature)
  editor.focus();
  const range = document.createRange();
  const sel = window.getSelection();
  range.setStart(editor.firstChild, 0);
  range.collapse(true);
  sel.removeAllRanges();
  sel.addRange(range);
  
  // 2. Build FQR HTML content
  const html = `<p>Dear [Customer Name],</p>
<p><br></p>
<p>Thank you for contacting Microsoft Support. My name is [Engineer Name], and I will be assisting you with case <b>[Case ID]</b>.</p>
<p><br></p>
<p><b>Issue Summary:</b></p>
<p>[Summary of the customer's issue from case description]</p>
<p><br></p>
<p><b>Analysis &amp; Findings:</b></p>
<p>[Analysis content - can be populated from B01 skill results]</p>
<p><br></p>
<p><b>Next Steps:</b></p>
<ul>
<li>[Action item 1]</li>
<li>[Action item 2]</li>
</ul>
<p><br></p>`;

  // 3. Dispatch ClipboardEvent (the ONLY method that works)
  const dt = new DataTransfer();
  dt.setData('text/html', html);
  editor.dispatchEvent(new ClipboardEvent('paste', {
    bubbles: true,
    cancelable: true,
    clipboardData: dt
  }));
  
  return 'FQR content pasted';
}
```

#### Implementation Notes (Gotchas)

1. **SSO Login**: First navigation redirects to SSO. Wait 8-10s. SSO auto-completes with cached credentials.
2. **Copilot Dialog**: DFM may show a Copilot popup on first load. Dismiss via `evaluate` clicking the dismiss/close button.
3. **Copilot Draft popup**: Inside the email editor, a "Draft with Copilot" card appears. Close it before injecting content.
4. **Search results**: After typing case ID in searchbox and pressing Enter, results appear in a treegrid. Double-click the case number cell to open it (single click only selects the row).
5. **CC lookup**: Search by **display name** (e.g., "Frank Shi"), not alias (e.g., "shile"). Alias search returns no results.
6. **CC "+1" badge**: After adding CC, an "Expand selected records" button with "+1" badge appears — this is normal, confirming the addition.
7. **Subject field**: **DO NOT MODIFY** — DFM auto-generates the subject from the case. Modifying it may cause tracking issues.
8. **Body editor type**: `contentEditable` div managed by CKEditor (RichTextEditorV2). It has an internal model that does NOT sync with direct DOM changes.
9. **Body injection**: **Preferred: `ckeditorInstance.setData()`** — directly updates CKEditor's internal model. Fallback: `ClipboardEvent('paste')` with `text/html` data. `innerHTML`, `insertHTML`, `execCommand('insertHTML')` all silently fail.
10. **Signature preservation**: The editor pre-loads the engineer's email signature in a `#signature` div. Position cursor at `editor.firstChild` (before signature) to insert content above it.
11. **Editor children**: Editor has 2 children: `[0]` = empty div for content, `[1]` = signature div. Always inject into position 0.
12. **Timeline navigation**: From case page, click "Timeline" tab → "Create a timeline record" button → "Email" menuitem from the Activity submenu.
13. **Session tabs**: Opening a case creates a new session tab in DFM. The email form opens as a sub-tab under the case session.
14. **Content clearing**: When re-pasting body content, use `selectNodeContents` + `document.execCommand('delete')` to clear. After clearing, position cursor at `editor, 0` (not `editor.firstChild, 0`) — using `firstChild` may leave residual fragments that appear after the newly pasted content.
15. **Customer Statement location**: Try `querySelector('[aria-label="Customer Statement"]')` first. If it returns null or empty, **immediately ask user to paste the content** — do NOT try alternative selectors.
16. **B01 before body**: **CRITICAL — this is the #1 efficiency rule.** Always run B01 analysis BEFORE opening the email form and injecting the FQR body. Generic placeholders in the email body result in low-quality FQR that must be rewritten after investigation, wasting ~50% of total time. The body should contain concrete findings derived from actual KQL queries.

#### Clearing Existing Body Content

If the editor already has content (e.g., from a previous paste or test), clear it before injecting new content:

```js
() => {
  const editor = document.querySelector('[aria-label="Rich Text Editor Control email description"]');
  if (!editor) return 'editor not found';
  editor.focus();
  const sel = window.getSelection();
  const range = document.createRange();
  range.selectNodeContents(editor);
  sel.removeAllRanges();
  sel.addRange(range);
  document.execCommand('delete', false, null);
  return 'content cleared, childCount: ' + editor.children.length;
}
```

> ⚠️ After clearing, the editor still has 2 child elements (content div + signature div). Always re-position cursor at `editor, 0` (not `editor.firstChild, 0`) before pasting new content to avoid residual fragments.

#### Reading Customer Statement from Case Page

Before drafting the FQR, navigate to the case page to read the **Customer Statement** (located in the "Restricted information" section). This provides the key context for the email body.

> ⚠️ **DFM's Restricted Information section uses deeply nested Dynamics 365 components whose DOM structure is unstable. Do NOT spend more than 1 attempt on DOM selectors. If the first attempt fails, immediately ask the user to paste the content.**

**Steps (with fast fallback):**
1. On the case page, try to read Customer Statement via `evaluate`:
   ```js
   () => {
     const cs = document.querySelector('[aria-label="Customer Statement"]');
     return cs ? cs.innerText : 'not found';
   }
   ```
2. **If result is "not found" or empty** → immediately ask user:
   ```
   Could not read Customer Statement from DFM DOM. Please paste the "Restricted information" 
   content here so I can proceed with the investigation.
   ```
3. Do NOT try additional DOM selectors (aria-label variants, data-id, scrolling, etc.) — this wastes 30-60s with unreliable results.

#### Integration with B01 Skill (Detailed Workflow)

The FQR body should contain **concrete, data-driven analysis** — not generic placeholders. Follow this workflow:

```
Step A: Read Customer Statement (see above)
        → Understand customer's specific asks and resource details

Step B: Identify Azure product from case metadata
        → Support Area path tells you the product (e.g., "Azure Firewall", "Application Gateway")
        → Load the corresponding B01 reference file from skills/b01/references/

Step C: Run B01 KQL queries sequentially
        1. Resource Info query → get firewall/gateway name, SKU, location, policy
        2. Policy/Config query → get IDPS mode, threat intel, TLS, DNS settings
        3. (Optional) Instance/infra query → get VM scale set, health status
        4. (Optional) Diagnostic log queries → get recent alerts, errors

Step D: Synthesize findings into FQR body
        → Issue Summary: paraphrase customer's asks (from Customer Statement)
        → Analysis & Findings: list concrete config/state discovered via B01
        → Next Steps: actionable items based on gaps found (e.g., "IDPS in Alert-only mode,
           no signature overrides configured — recommend reviewing alert logs to identify
           false positives before switching to Deny mode")
```

#### End-to-End FQR Automation Sequence

> ⚠️ **CRITICAL: MUST follow this exact order. Do NOT write the FQR body before completing Step 4 (B01 investigation). Writing the email first and rewriting after investigation wastes ~50% of total time.**

```
Phase 1 — Information Gathering (BEFORE opening email form)
  1. User provides Case ID + CC display name
  2. Navigate to DFM → search case → open case page
  3. Read Customer Statement:
     → First try: evaluate querySelector('[aria-label="Customer Statement"]').innerText
     → Fallback: ask user to paste Restricted Information content
     (DFM's Restricted Information section uses dynamic components whose
      DOM structure changes across sessions — do NOT spend more than 1 attempt
      on DOM selectors. If the first attempt fails, immediately ask the user.)
  4. Identify product from Support Area Path → load B01 reference
     → Run KQL queries (NRP/ARM operations for API errors, product-specific
        queries for config/health issues)
     → Extract concrete findings: exact error fields, root cause, request body, etc.

Phase 2 — Email Composition (AFTER investigation is complete)
  5. Navigate to Timeline → Create Email
  6. Add CC if needed (type display name slowly → click treeitem)
  7. DO NOT modify Subject
  8. Synthesize B01 results + Customer Statement into FQR body HTML
  9. Inject FQR HTML via CKEditor API (see Body Editor Injection below)
  10. Present to user for review → user sends or saves
```
